# ADR 0004: AI 嵌入方向

## 状态

已规划，暂不实施 (2026-05-22)

## 背景

项目正式版本上线后拟嵌入 AI 辅助功能。需提前确定技术选型兼容性和功能优先级。

## 决策

### 技术路线

前端保持现有 React 选型，不因 AI 嵌入引入新框架。AI 通信通过后端新增端点统一管理。

### 功能优先级

| 优先级 | 场景                 | 形式                                             | 触发条件                            |
| ------ | -------------------- | ------------------------------------------------ | ----------------------------------- |
| P0     | 活动方案模板智能填充 | AI 根据活动基本信息自动生成方案初稿              | 用户输入关键参数后点击"AI 辅助生成" |
| P0     | 对话式活动面板       | 自然语言查询面板数据（"本月取消的活动有哪些？"） | 用户点击 AI 助手侧边栏输入          |
| P1     | 附件合规自检         | 上传后自动扫描提示格式/分辨率问题                | 文件上传后自动触发                  |
| P2     | 驳回意见摘要         | 长文本审批意见提炼为待办清单                     | 安保部驳回后自动生成                |
| P2     | 逾期风险预警         | 根据历史耗时预测当前活动延误概率                 | 后台定时检测                        |
| P3     | 审批决策建议         | 侧边栏展示相似活动的审批结果统计                 | 审批人进入审批页时                  |
| P3     | 批文 OCR 解析        | 政府批文扫描件提取关键字段                       | 上传批文后自动触发                  |

### 架构约束

- 所有 AI 请求通过后端 `/ai/*` 端点统一处理（不从前端直接调外部 AI API）
- AI 会话上下文在 Zustand 中管理（当前活动的审批历史作为 prompt 前缀）
- 文件解析（OCR）在后端完成，前端只展示结果
