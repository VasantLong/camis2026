# ADR 0003: 前端技术选型

## 状态

已采纳 (2026-05-22)

## 背景

后端为 FastAPI REST API（18 个端点 + RBAC + 文件上传/下载）。需确定前端技术栈以支持：活动方案设计（表单 + 文件上传）、审批流转（状态同步 + 时间线）、活动面板（数据可视化）、AI 辅助（未来版本嵌入）。

## 决策

采用 **React SPA + 前后端分离**：

| 层面 | 选择 | 理由 |
|------|------|------|
| 框架 | React 18+ | 团队已有经验，非学习成本项 |
| 构建 | Vite | 行业标准，HMR 极快，CRA 已停维 |
| UI 组件 | Ant Design 5 | 企业级中文风，Table/Form/Timeline/Steps/Upload 全内置，直接映射审批 MIS 交互模式 |
| 服务端状态 | TanStack Query | API 缓存、自动重取、loading/error 状态管理，天然适配活动列表/审批状态/面板数据的服务端数据读取 |
| 客户端状态 | Zustand | 极简 API，管理表单草稿、UI 开关、筛选条件等前端自身状态 |
| 文件上传 | Ant Design Upload + 后端 `/documents/upload` | 不额外引入第三方上传库 |
| AI 嵌入（未来） | Vercel AI SDK | 支持流式响应、`useChat`/`useCompletion` hooks，无框架冲突 |

## 替代方案

- **Next.js 全栈**：需重写已有 FastAPI 后端（29 测试/18 端点），代价过大
- **Next.js 纯前端**：相比 Vite SPA 无本质优势，只多了 SSR 复杂度
- **Vue**：团队无 Vue 经验，且 Ant Design 的 Vue 版本功能滞后

## 影响

- 前端部署：Nginx 静态托管 dist + 反向代理到 FastAPI
- 与后端完全解耦，前端选型变更不影响后端
