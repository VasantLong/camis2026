# ADR 0002: 采用 RBAC 用户模型

## 状态

已采纳 (2026-05-21)

## 背景

初始类图将四类员工建模为独立类（Promoter, SecurityOfficer, AdminStaff, GovLiaison），各有属性和方法。但现实中同一员工可能承担多个岗位职责，独立类会导致数据冗余和身份割裂。

## 决策

采用 **RBAC (Role-Based Access Control)** 模型：

- `User`：统一身份（登录凭证、基本信息）
- `Role`：岗位角色（Promoter, SecurityOfficer, AdminStaff, GovLiaison）
- `Permission`：操作权限（create_project, upload_plan, approve_security 等）
- User 与 Role 为多对多关系

## 理由

1. **人员复用**：同一人可能兼任宣策部和安保部角色，RBAC 天然支持
2. **权限粒度**：UC1 的创建立项和 UC2 的编制方案同属 Promoter，但权限不同。Permission 可以细粒度控制每个操作
3. **行业标准**：企业 MIS 系统普遍采用 RBAC，符合审计和合规要求

## 影响

- 类图中四个 Actor 类合并为一个 User，新增 Role、Permission
- 已有 `users` 表需扩展角色关联表
- 顺序图中 Actor lifeline 无需改动（角色语义保留，只是建模方式变了）
